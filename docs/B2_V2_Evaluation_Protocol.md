# B2 Spiral V2 independent evaluation protocol

Frozen fixture: `evidence/b2-v2-public-fixture-2026-10-31.json`, SHA-256 `a06200b7454504175836b337718788ea59b5490486c4893163b540acfede44e5`. It was assembled before the first model run on 2026-10-31. Source URLs and source-file hashes are embedded in the fixture. The 48 tasks came from public GSM8K test, BIG-Bench Hard Boolean Expressions and Formal Fallacies, HumanEval, and AlpacaEval. They are new to Seren's local development probes, but public availability means Falcon may have encountered them during pretraining.

The disjoint 24-task confirmation fixture is `evidence/b2-v2-confirm-fixture-2026-10-31.json`, SHA-256 `a4a75ae96139fff5e79544c6252daef64b64b55d7cb9fb4a7d9e1618e2255429`. It has six semantic cases requiring blinded human grading. Both fixtures are public and may appear in model pretraining.

## Locked procedure

Run `node tools/b2_public_eval.mjs public` or `node tools/b2_public_eval.mjs confirm` from the repository root with the unchanged fixture and one pinned Falcon-H1-Tiny 90M Instruct GGUF. The script refuses a fixture hash change. Both arms use the same model Worker, tokenizer, prompt template, temperature 0.2, and at most 128 generated tokens per call. Falcon alone gets the published request. Falcon+B2 receives the same request through `SpiralController`; its strategy may add tool operations or calls. Each case is run once per arm. Even fixture indices use A→B; odd indices use B→A. B2 has a separate scope per case and no persisted calibration input, preventing cross-case exact-state reuse or leakage into routing. The model is loaded before timing both arms. Record raw answers, error, trace, model calls, calculator calls, cache hits, token count, latency, and sampled Node+browser process-tree RSS. The RSS includes harness overhead and is not isolated model memory.

## Scoring

- Mathematics: compare the last numeric claim in the answer to the published GSM8K final number. This is a conservative machine proxy; inspect any answer containing conflicting claims before treating it as correct.
- Boolean logic and formal fallacies: accept only an unambiguous published choice, with no opposite choice in the response.
- Coding: run the published HumanEval functional tests through `tools/b2_python_check.py`. The checker accepts a restricted Python AST, removes typing imports from the generated answer, provides only an allowlist of builtins/methods, and executes in a child process with a CPU limit and parent timeout. All eight selected canonical solutions pass this checker. Unsupported generated syntax counts as a failed executable outcome, and the reason is recorded. macOS refused `RLIMIT_AS`, so the checker does not claim a hard memory cap. Generated code has no import, arbitrary attribute, filesystem, or network capability through the restricted namespace; this is not a general sandbox for arbitrary Python.
- Planning and ordinary conversation: machine score stays `pending_human`. Produce a pairwise review packet with system labels hidden and a separate key. The reviewer should score each response 0 (wrong/off-topic), 1 (partly useful), or 2 (correct/useful); identify concrete flaws; then choose response 1, response 2, or tie. A human preference is not an independent proof of factual claims.

The evaluator creates a blank `b2-v2-human-grades-*.json`. A reviewer fills its 14 items while reading only the blind packet. After grading, run `node tools/b2_score_human_review.mjs <completed-grades.json> <blind-key.json>` to unblind into a separate scored receipt. Unfilled grades do not count as a tie or pass.

Do not inspect the blind key before grading. Do not tune B2 on the frozen fixture and rerun it as though it were held out. If changes are made after seeing outcomes, use new independently selected tasks and keep all negative results. General reasoning improvement requires checked gains across categories, no material regressions, and completed human review; it cannot be inferred from a single aggregate accuracy number.
